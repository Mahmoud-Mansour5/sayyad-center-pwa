# 📚 نظام إدارة مركز الأستاذ محمود الصياد للتطوير التعليمي

تطبيق ويب تقدمي (PWA) يعمل **أوفلاين بالكامل**، مخصص لإدارة الحضور والدرجات والملاحظات في المراكز التعليمية، مع مزامنة تلقائية للبيانات مع الخادم عند توفر الاتصال بالإنترنت.

---

## 🗂️ محتويات المشروع

| الملف | الوظيفة |
|---|---|
| `index.html` | الهيكل الأساسي للتطبيق (الواجهات، القوالب، النوافذ المنبثقة) |
| `styles.css` | التنسيقات الكاملة للتطبيق (تصميم متجاوب، دعم RTL) |
| `app.js` | منطق التطبيق: المصادقة، المزامنة، العرض، الصلاحيات |
| `db.js` | طبقة التخزين المحلي (IndexedDB) مع نسخة احتياطية بـ localStorage |
| `sw.js` | Service Worker لتفعيل العمل أوفلاين والتخزين المؤقت |
| `manifest.json` | إعدادات تثبيت التطبيق كتطبيق PWA على الجوال/سطح المكتب |

---

## ✨ أهم الميزات

### 1. عدم الاعتماد على بيانات ثابتة (Dynamic Data)
- تم حذف قوائم الطلاب والمستخدمين الثابتة (`SEED_STUDENTS` و `CONFIG.USERS`) بالكامل من الكود.
- عند فتح التطبيق لأول مرة وتوفر اتصال بالإنترنت، تُستدعى الدالة `fetchInitialData()` تلقائيًا لجلب:
  - **قائمة الطلاب** (`students`)
  - **الإعدادات** (`settings`): الصفوف الدراسية، الفروع، الأيام، المواعيد
  - **حسابات السكرتارية** (`secretaries`): الاسم، الرقم السري، الدور، والمجموعات المسموح بها
- كل هذه البيانات تُخزَّن محليًا داخل `IndexedDB` لتعمل بكفاءة حتى بدون إنترنت في الزيارات القادمة.
- **تسجيل الدخول أصبح يعتمد على قاعدة البيانات المحلية** بدلًا من أي أرقام سرية مكتوبة داخل الكود.

> ⚠️ **ملاحظة هامة قبل الاستخدام الفعلي:**
> يجب استبدال القيمة التالية في أعلى ملف `app.js` برابط الـ API الحقيقي الخاص بك:
> ```js
> API_ENDPOINT: 'https://script.google.com/macros/s/REPLACE_WITH_YOUR_DEPLOYMENT_ID/exec'
> ```
> وطالما لم يتم استبدال هذا الرابط، سيعمل التطبيق في **وضع تجريبي محلي بالكامل** (بدون إرسال أو استقبال بيانات فعلية من أي خادم)، وستحتاج إلى إضافة حسابات السكرتارية يدويًا عبر أدوات المطوّر أو عبر endpoint فعلي حتى يتمكن أي مستخدم من تسجيل الدخول.

---

### 2. إضافة طالب جديد (أوفلاين أولًا)
- زر **➕** في أعلى الشاشة (يظهر فقط لحسابات السكرتارية).
- نافذة إضافة طالب تحتوي على:
  - اسم الطالب
  - رقم هاتف ولي الأمر
  - 4 قوائم منسدلة: **الصف الدراسي / الفرع / اليوم / الموعد** (تُملأ تلقائيًا من الإعدادات المخزنة محليًا)
- عند الحفظ:
  - يُنشأ معرّف مؤقت للطالب بالشكل `NEW_<timestamp>`
  - يُحفظ الطالب فورًا في `IndexedDB` بحالة `syncStatus: 'pending_creation'`
  - تظهر بطاقة الطالب فورًا في القائمة مع شارة **🆕 بانتظار المزامنة**، ويمكن للسكرتارية تسجيل حضوره ودرجاته مباشرة دون انتظار الاتصال بالإنترنت
- عند توفر الإنترنت، يقوم محرك المزامنة (`triggerSync`) تلقائيًا بإرسال جميع الطلاب الجدد إلى الخادم، وتتغيّر حالتهم إلى `synced` بعد نجاح الإرسال.

---

### 3. صلاحيات السكرتارية (Role-Based Access Control)
- كل حساب سكرتارية يحتوي على مصفوفة `allowedGroups` تحدد المجموعات التي يحق له متابعتها فقط.
- تم تحديث دالة `getFilteredStudents()` بحيث:
  - **المدير (master)** يرى جميع الطلاب دون قيود.
  - **السكرتارية** ترى فقط الطلاب المنتمين إلى المجموعات المسموح بها لها. إذا كانت `allowedGroups` فارغة، تُعامل كحساب بدون قيود (للتوافق مع الحسابات القديمة).
- زر **⚙️ إدارة السكرتارية** يظهر فقط في شاشة المدير، ويفتح نافذة تعرض جميع حسابات السكرتارية المخزنة محليًا مع:
  - حالة المزامنة الخاصة بكل حساب
  - عدد المجموعات المسموحة حاليًا
- عند الضغط على **"تعديل المجموعات المسموحة"**:
  - تظهر قائمة بجميع المجموعات المعروفة (من الإعدادات ومن قائمة الطلاب الفعلية)
  - يمكن للمدير تحديد/إلغاء تحديد المجموعات عبر خانات اختيار (Checkboxes)
  - عند الحفظ، يُعلَّم الحساب بـ `pendingSync: true` ليُرسَل تلقائيًا إلى الخادم عند توفر الاتصال

## 🔄 آلية المزامنة (Sync Engine)

يعمل `triggerSync()` تلقائيًا في الخلفية (عند استعادة الاتصال، أو كل 30 ثانية كمحاولة احتياطية)، ويقوم بإرسال ثلاثة أنواع من البيانات المعلّقة بالترتيب:

1. **الطلاب الجدد** المضافين أوفلاين (`syncStatus: 'pending_creation'`)
2. **تحديثات صلاحيات السكرتارية** (`pendingSync: true`)
3. **سجلات الحضور والدرجات المعتمدة** من المدير (`status: 'approved'` أو `'failed'`)

كل عنصر يُرسل بشكل مستقل، وفي حال فشل الإرسال (بسبب انقطاع الاتصال مثلًا) تبقى حالته معلّقة ليُعاد إرسالها تلقائيًا في المحاولة التالية دون أي تدخل يدوي.

## 🗄️ هيكلة قاعدة البيانات المحلية (IndexedDB)

| المخزن (Object Store) | المفتاح الأساسي | الوصف |
|---|---|---|
| `students` | `id` | قائمة الطلاب (شاملة الطلاب الجدد بحالة `pending_creation`) |
| `records` | `recordId` | سجلات الحضور/الدرجات/الملاحظات اليومية |
| `settings` | `key` | قوائم الإعدادات (`branches`, `years`, `days`, `times`, `groups`) |
| `secretaries` | `id` | حسابات تسجيل الدخول والصلاحيات |
| `meta` | `key` | بيانات تشغيلية عامة (مثل وقت آخر مزامنة) |

> عند عدم توفر `IndexedDB` (حالات نادرة مثل بعض أوضاع التصفح الخاص)، يتحول التطبيق تلقائيًا إلى نسخة بديلة باستخدام `localStorage` دون أي تغيير في سلوك الواجهة.

## 🚀 خطوات التشغيل والتجربة

1. ضع جميع الملفات (`index.html`, `styles.css`, `app.js`, `db.js`, `sw.js`, `manifest.json`) في نفس المجلد، مع مجلد `icons/` يحتوي على أيقونات التطبيق بالمقاسات المذكورة في `manifest.json`.
2. شغّل المجلد عبر أي خادم محلي (مثال: `npx serve .` أو إضافة Live Server)، لأن Service Worker لا يعمل عند فتح الملف مباشرة (`file://`).
3. افتح التطبيق من المتصفح — سيظهر شعار التحميل ثم شاشة تسجيل الدخول.
4. **لتجربة النظام دون ربط API حقيقي:** أضف حسابات تجريبية يدويًا من أدوات المطوّر (Console) كالتالي:

```js
db.upsertSecretary({
  id: 'sec-1',
  name: 'سكرتارية الاستقبال',
  pin: '1234',
  role: 'secretary',
  allowedGroups: [] // فارغة = بدون قيود
});

db.upsertSecretary({
  id: 'master-1',
  name: 'الأستاذ محمود الصياد',
  pin: '9999',
  role: 'master'
});
```

ثم أعد تحميل الصفحة وسجّل الدخول بالأرقام السرية أعلاه.

## 🔐 ملاحظات أمنية

- الأرقام السرية تُخزَّن حاليًا كنص عادي في `IndexedDB` لأغراض العمل أوفلاين. يُنصح بشدة عند ربط الخادم الفعلي بتطبيق تجزئة (hashing) على الأرقام السرية من جهة الخادم، والتحقق منها عبر طلب مصادقة فعلي بدل الاعتماد الكامل على النسخة المخزنة محليًا.
- يُفضّل تحديث بيانات `secretaries` بشكل دوري من الخادم لضمان إلغاء صلاحية أي حساب مباشرة عبر إعادة المزامنة.

## 📌 ملخص التغييرات الرئيسية عن النسخة السابقة

- ✅ حذف البيانات التجريبية الثابتة بالكامل من `app.js` و `db.js`
- ✅ إضافة مخزنين جديدين في قاعدة البيانات: `settings` و `secretaries`
- ✅ دالة `fetchInitialData()` لجلب البيانات الحية من الخادم وتخزينها أوفلاين
- ✅ نافذة "إضافة طالب جديد" بتدفق عمل أوفلاين كامل
- ✅ تحديث محرك المزامنة ليشمل الطلاب الجدد وتحديثات صلاحيات السكرتارية
- ✅ نظام صلاحيات كامل (RBAC) يقيّد رؤية السكرتارية بمجموعاتها المسموحة فقط
- ✅ نافذة "إدارة السكرتارية" لضبط الصلاحيات من شاشة المدير
